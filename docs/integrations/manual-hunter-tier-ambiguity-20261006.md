# Manual-hunter review-tier ambiguity fix

- **Feature branch:** `fix/manual-hunter-tier-ambiguity-20261006` (based on `origin/beta` at `59e72403600c9e9035081ca32e7ac5c64f3bbd83`).
- **Scope:** `agents/manual_hunter.py`, `agents/sync_reports.py`, `agents/report_checker.py`, and focused tests. Existing stored findings are not re-tiered.
- **Current defect:** A note describing an observed/reproduced cross-account read and saying its impact *may* extend was silently classified `DORMANT_HYPOTHETICAL` because broad uncertainty markers in description overrode the actual proof. A synthetic current-beta repro demonstrated the mis-tier; no live target was touched.
- **Fix:** An invalid explicit tier is rejected before any missing-field or loose fallback can guess a tier. Conflicting repeated `Review Tier:`/`Tier:`/`Status:` fields and conflicts between a structured `[TIER]` heading and a field in the same finding are rejected; standard `**Tier:**` Markdown is parsed without including bold markers in the value. Neutral `Exploitability`, `Blocked Reason`, and `Chain Requirements` are normalized before inference. For an unlabelled note with uncertainty and an evidence signal (structured PoC/Review Notes or an observed-response phrase), the author must explicitly select `Review Tier:`; a bare unproven *may/might* claim continues to infer `DORMANT_HYPOTHETICAL`. `sync_reports` skips unresolved notes with an actionable error and nonzero return, but honors valid per-finding `[CONFIRMED]`/`[DORMANT_...]` Markdown headings instead of whole-file loose-parser ambiguity. The shared report loader recognizes structured headings at byte zero; sync rejects unmatched heading/record counts and unsupported tier names in headings rather than inferring from a misspelled decision or silently importing a subset. No automatic promotion of uncertain claims.
- **Red/green:** Original synthetic regression failed before the initial change. Focused RED tests covered these cases, including unmatched-heading-count and invalid-heading guards, and passed after repair.
