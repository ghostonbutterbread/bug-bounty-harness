# JS XSS sink inventory (static review seeds)

`agents/js_analyzer.py` scans downloaded JS **bundle text** for its legacy `sinks` field. It separately inventories embedded source-map modules and writes review packets for their source; the legacy broad `sinks` pass does **not** independently scan each module's text, while the new individual `sink_sites` pass scans only packetized modules within source-map budgets. The `sinks` field is a **sorted list of broad review categories**, not call sites or a source-to-sink trace. The `signal_coverage.exhaustive` value remains `false`. A hit only means a pattern occurs in inventoried text; a miss cannot establish safety. Dynamic property names, minification, template expansion, unpacketized source-only modules, missing bundles, aliases, parser context, and browser/runtime paths need agent review.

The existing `dom_write`, `script_create`, `navigation`, `eval`, `request`, and `storage_write` labels remain for JSONL consumers. Added XSS review labels:

- `html_parse`: HTML parsing and unsafe insertion (`parseFromString`, `parseHTMLUnsafe`, `setHTMLUnsafe`, `createContextualFragment`, `execCommand('insertHTML')`, and variable-fed fbjs `createNodesFromMarkup`). Parsing alone may be inert; follow where the fragment is inserted.
- `iframe_srcdoc`, `event_handler`, `event_handler_candidate`: iframe HTML (including writes through an iframe's `attributes.srcdoc` node), known browser event-handler attributes/properties, and lower-confidence unfamiliar `on*` properties. Ordinary fields such as `one`, `once` and `only` are excluded; a function-valued `onclick` assignment alone is not injection.
- `jquery_html`, `jquery_html_property`, `jquery_parse`, `jquery_attribute`, `jquery_selector_candidate`, `jquery_alias_candidate`, `jquery_legacy_candidate`: jQuery/AngularJS HTML insertion (including `appendTo`/`prependTo`), `.prop('innerHTML'/'outerHTML', value)` setters, parser, URL/event-sensitive attributes, location-fed selector use, bounded one-hop jQuery receiver aliases, and unusual jQuery candidates. HTML-inserting method signatures require an observable `$()`/`jQuery()`/`angular.element()` receiver and a nonempty argument; `.attr()`/`.prop()` require a setter argument after the sensitive attribute name. Getter calls and native `Element.append`, `prepend`, `before` and `after` are excluded. Bounded alias/selector and legacy categories are **candidates**, not taint traces or XSS findings; unrecognized aliases need human review.
- `framework_raw_html`, `framework_template_candidate`, `framework_trust_bypass`, `trusted_types_policy_candidate`: React, Vue, Angular/AngularJS, Svelte, Lit, Alpine, Astro and Solid raw HTML; Lit `unsafeSVG`; Angular Renderer2 HTML-property writes; variable-fed Vue runtime templates; Angular sanitizer/$sce trust bypass including `trustAsJs`; Handlebars SafeString and Trusted Types policy creation/use. Template candidates require a runtime compiler and a plausible dynamic argument (including bounded comment-prefixed forms); fixed literals and empty/null values are excluded; a trust wrapper or policy is **not a standalone execution sink**—inspect its implementation and downstream renderer.
- `script_content`, `script_alias_candidate`, `script_import`, `script_import_candidate`, `url_attribute`: script text/URL assignment (including quoted property keys), bounded script-element aliases and content writes, worker/dynamic imports and jQuery `getScript`, jQuery AJAX configured for script response, and URL-bearing attributes. Script aliases and AJAX script mode are **candidates**; element kind, scheme, origin, CSP, user interaction and controllability matter.

`dom_write` also recognizes literal bracket calls such as `document['write']` and `el['insertAdjacentHTML']`; `navigation` recognizes constant-key bracket assignments to `location`/`href`, as well as Navigation API and qualified `window.open`. Unqualified `open(...)` is retained under `unqualified_open_candidate` because static text cannot always distinguish `window.open` from unrelated functions or XHR usage. These and `url_attribute` are **conditional URL sinks**, not equivalent to HTML injection. `eval` includes direct `eval`/Function and jQuery `globalEval`; `string_timer_candidate` covers string/variable timer arguments but does not assert that a variable is code rather than a callback. `event_handler` property assignments also need value-type review. `request` and `storage_write` are legacy general inventory categories, **not direct XSS execution sinks**.

## Individual XSS execution-site review seeds

The broad `sinks` list remains compatible with existing JSONL consumers, but it is **not a count of APIs or call sites**. The companion `sink_sites` list names each matched API/attribute/directive and records `{signature, family, tier, start, end}` with character offsets into the original downloaded bundle. `metadata.jsonl` preserves its URL, SHA-256, page context and artifact path; `packets/*.md` shows matched sites within each chunk. Packetized embedded source-map modules carry separate `sink_sites` in `source_map_modules.jsonl` and their module packets; modules without content or skipped by the existing expansion budget remain unscanned. The manifest reports `sink_site_hits` and `sink_site_capped_artifacts`.

The catalog currently has **218 named signatures**: **108** are named event-handler property/attribute/namespace spellings, not 108 distinct ways to execute JavaScript. The remaining signatures distinguish HTML writes/parsers, iframe `srcdoc`, script text/URL, eval/Function/string timers, script/worker loaders, navigation and URL attributes, jQuery insertion/attribute methods, and framework raw markup/template/trust APIs. A further bounded script-element alias pass reports text-node insertion and property writes, with limited block-scope tracking for rebinding and shadowed function/arrow parameters; jQuery method signatures recognize up to two bounded jQuery-preserving chain methods. The dynamic `$()` constructor candidate is restricted to location hash/search and plausible HTML/input variable names so common `$(el)` wrappers do not consume its hit cap; other computed values still require manual review. This is **not an exhaustive browser or framework sink inventory** and does not include server-only EJS/Pug/Mustache rendering, inline server HTML, dynamically generated code, or all source-map modules. The executable’s legacy label count and the named-signature count are different metrics.

`html` = a parser/rendering destination, `code` = code-evaluation or script-text context, `url` = executable only under relevant scheme/origin/element/CSP conditions, and `candidate` = receiver, argument type, version, later insertion or consumer must be verified. **None of these tiers proves attacker control or an XSS vulnerability.** A raw `innerHTML` assignment does not execute an inserted `<script>` tag in modern browsers; event handlers and later parsing can matter. Literal script creation/append and indirect wrappers need element identity and insertion checks. The output is capped at 8 hits per signature and 200 hits per artifact; `sink_sites_truncated` is set when those limits or the bounded anchor-window budget are reached. Offsets are Unicode character indexes (not byte offsets); they reference the complete bundle or original source module, not a chunk-relative snippet. Fixed selectors, getters, equality reads, text-only writes, non-HTML MIME parsing, function-valued timers and plain-object `Object.assign` have explicit negative fixtures, but static matches can still be false positives.

Use the same scoped `bbh agents/js_analyzer.py inventory <program> --input <js-url-list> --target-host <in-scope-host>` route from the XSS skill. Collection may fetch JS and maps; this site pass itself is static. Review the exact matched code, value provenance and browser execution before upgrading any seed.

## Primary references checked

- [PortSwigger Web Security Academy: DOM-based XSS, including jQuery sink list](https://portswigger.net/web-security/cross-site-scripting/dom-based). It lists broad candidates including `document.domain`; we intentionally omit `document.domain` as a direct XSS sink because setting it alone does not interpret untrusted HTML or JavaScript.
- [PortSwigger DOM Invader testcases](https://portswigger-labs.net/dom-invader/): cross-check for jQuery globalEval/wrap, `importScripts`, Navigation API, and core DOM sinks. Testcases are not an authoritative exhaustive sink taxonomy.
- [OWASP DOM-based XSS Prevention Cheat Sheet](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/DOM_based_XSS_Prevention_Cheat_Sheet.md): HTML insertion, `setAttribute` coercion, eval/string timers, and URL context. Safe text APIs are deliberately excluded from high-confidence categories.
- [CodeQL JavaScript DOM model](https://github.com/github/codeql/blob/main/javascript/ql/lib/semmle/javascript/security/dataflow/DOM.qll), [DOM-XSS query](https://github.com/github/codeql/blob/main/javascript/ql/lib/semmle/javascript/security/dataflow/DomBasedXssQuery.qll), and [framework sink customizations](https://github.com/github/codeql/blob/main/javascript/ql/lib/semmle/javascript/security/dataflow/DomBasedXssCustomizations.qll): distinguish HTML, URL, jQuery, and trust-bypass semantics. Structural DOM methods such as `appendChild` are not promoted to direct XSS sinks without the created element/content path.
- [Dalfox AST DOM sink list](https://github.com/hahwul/dalfox/blob/main/src/scanning/ast_dom_analysis/mod.rs) and [receiver/argument checks](https://github.com/hahwul/dalfox/blob/main/src/scanning/ast_dom_analysis/sinks.rs): cross-check of HTML parsing, script content, URL and event sinks, including explicit guards against native text insertion being mistaken for jQuery HTML insertion.
- [Semgrep browser](https://github.com/semgrep/semgrep-rules/blob/develop/javascript/browser/security/insecure-document-method.yaml), [jQuery](https://github.com/semgrep/semgrep-rules/blob/develop/javascript/jquery/security/audit/jquery-insecure-method.yaml), and [Angular](https://github.com/semgrep/semgrep-rules/blob/develop/javascript/angular/security/detect-angular-trust-as-html-method.yaml) rules: additional static seed signatures, not a complete sink taxonomy.
- [XSStrike DOM recognizer](https://github.com/s0md3v/XSStrike/blob/master/core/dom.py): cross-check of legacy code execution, script element, fragment, navigation, and HTML write signatures. Its broad `evaluate`/`assign`/modal-dialog and other legacy terms are not copied blindly as direct XSS proof.
- [React raw HTML](https://react.dev/reference/react-dom/components/common#dangerously-setting-the-inner-html), [Vue `v-html`](https://vuejs.org/guide/essentials/template-syntax.html#raw-html), [Angular DomSanitizer bypass](https://angular.dev/api/platform-browser/DomSanitizer), [Svelte `{@html}`](https://svelte.dev/docs/svelte/@html), [Lit `unsafeHTML`](https://lit.dev/docs/templates/directives/#unsafehtml), [Alpine `x-html`](https://alpinejs.dev/directives/html), [Astro `set:html`](https://docs.astro.build/en/reference/directives-reference/#sethtml), [Solid `innerHTML`](https://docs.solidjs.com/reference/jsx-attributes/innerhtml), and [jQuery `.html()`](https://api.jquery.com/html/): framework-specific raw rendering and trust bypasses.

- [PortSwigger DOM Invader `srcdoc` attribute-node](https://portswigger-labs.net/dom-invader/testcases/augmented-dom-iframe-srcdoc-nodevalue/), [script `appendChild`](https://portswigger-labs.net/dom-invader/testcases/augmented-dom-script-appendchild/), and [jQuery `$()` constructor](https://portswigger-labs.net/dom-invader/testcases/augmented-dom-jquery-%24/) cases: evidence for alternate spellings and bounded one-hop candidates, not an exhaustive list or browser proof for every matching bundle.
- [jQuery `.attr()`](https://api.jquery.com/attr/) and [`.prop()`](https://api.jquery.com/prop/) distinguish HTML attributes from DOM properties: only `.prop('innerHTML'/'outerHTML', value)` receives the HTML-property label; `.attr('innerHTML', value)` is not a DOM HTML setter.
- [Vue template security guidance](https://vuejs.org/guide/best-practices/security.html) specifically covers concatenating user content into a quoted template; dynamic template literals are also candidate signals, while fixed literals are excluded. [Angular Renderer2 API](https://angular.dev/api/core/Renderer2), [Lit `unsafeSVG`](https://lit.dev/docs/templates/directives/#unsafesvg), and [jQuery `getScript`](https://api.jquery.com/jQuery.getScript/) support the additional framework/script-loader candidates.
- [Semgrep fbjs `createNodesFromMarkup`](https://github.com/semgrep/semgrep-rules/blob/develop/javascript/fbjs/security/audit/insecure-createnodesfrommarkup.yaml) and [AngularJS `$sce.trustAsJs`](https://github.com/semgrep/semgrep-rules/blob/develop/javascript/angular/security/detect-angular-trust-as-js-method.yaml) rules: additional parser and trust-bypass seeds, never independent execution proof.

- [CodeQL DOM-XSS customizations](https://github.com/github/codeql/blob/main/javascript/ql/lib/semmle/javascript/security/dataflow/DomBasedXssCustomizations.qll), [Dalfox AST sink model](https://github.com/hahwul/dalfox/blob/main/src/scanning/ast_dom_analysis/sinks.rs), and [XSStrike DOM recognizer](https://github.com/s0md3v/XSStrike/blob/master/core/dom.py): individual API spellings are cross-checked, but receiver/argument conditions in their models are **not reproduced as taint analysis** by this inventory. `Object.assign` needs a DOM target; WinJS unsafe insertion is a library-qualified site, not a generic helper name.
- [PortSwigger DOM Invader testcase index](https://portswigger-labs.net/dom-invader/), including [iframe `srcdoc` attribute-node](https://portswigger-labs.net/dom-invader/testcases/augmented-dom-iframe-srcdoc-nodevalue/), [script text-node insertion](https://portswigger-labs.net/dom-invader/testcases/augmented-dom-script-appendchild/), and [dynamic jQuery construction](https://portswigger-labs.net/dom-invader/testcases/augmented-dom-jquery-%24/): scenarios and alternative spellings, **not** one distinct sink per testcase.
- [AngularJS `$compile`](https://docs.angularjs.org/api/ng/service/$compile), [Lit `unsafeStatic`](https://lit.dev/docs/api/static-html/), [MDN Worker constructor](https://developer.mozilla.org/en-US/docs/Web/API/Worker/Worker), and [Semgrep jQuery selector rule](https://github.com/semgrep/semgrep-rules/blob/develop/javascript/jquery/security/audit/jquery-insecure-selector.yaml): conditional runtime template, worker-script, and possible HTML-prefix sites; source-to-consumer and version remain to be checked.

Not copied as direct XSS execution: PortSwigger's `document.domain`, CSS-only writes, ordinary text-node insertion, general `appendChild`, modal-dialog/XPath APIs, and legacy `setImmediate`/`crypto.generateCRMFRequest`. Those terms need a relevant consumer/runtime or an explicit source-to-execution trace; adding them as unconditional sink labels would drown the inventory in unrelated hits. Server EJS/Mustache unescaped templates, unpacketized source-map modules, and runtime-generated scripts are outside this **bundle-and-packetized-module** pass and remain separate review surfaces.

Do not promote a regex hit into `Confirmed` without an attacker-controlled source, its transformations and a browser execution proof. Reconcile the inventoried bundle/page coverage before treating any zero-hit result as meaningful.
