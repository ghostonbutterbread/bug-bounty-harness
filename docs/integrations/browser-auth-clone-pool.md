## Implemented boundaries

The program-scoped `single`/`multiple` policy is stored by exact program with categorical evidence and CLI set/show readback. Its common admission predicate covers provisioner selection and canonical acquire/transfer: program `single` dominates exact-account `multiple`; exact-account/domain `single` dominates program `multiple`; unknown/absent program mode preserves the legacy exact-account behavior. The policy does not turn an unauthenticated browser into a clone and does not silently broaden another program/domain/account. Active leases are not changed by policy writes; logout remains passive evidence, not a switch to `multiple`.

The canonical private transfer identity/grant tables default to **no attestation** for existing rows. Manager attestation does not issue production grants. `manager_fixture_auth_transfer` is a private Python fixture transaction, not a CLI/HTTP/general account endpoint. It accepts only manager-derived owners matching exact `(fixture, fixture.invalid, anon)` and an exact loopback `http://127.0.0.1:<port>` origin, with a fixed fixture `/whoami` principal check, one HttpOnly cookie, and one selected-origin localStorage key. It refuses mismatched owners, program, domain, account, origin, physical profiles, process/unit and CDP identities. Source and destination use separate live Chrome profiles. Exclusive adapter tickets and a quarantine/commit/activate sequence fence public CDP across transfer and uncertain replies; exact destination disposal is attempted when the end/commit outcome is uncertain. A failed exact stop remains `destination-cleanup-incomplete` and requires operator disposal; no source stop or raw profile copying. No caller-provided identity, auth payload, script, or site definition is accepted. No pool generation, peer promotion, or production site adapter is implemented.

Latest `origin/beta` browser-history repairs were reconciled at `4840f82`; the fetched `d077b89` base also carries generic startup diagnostics. Git reported no textual conflicts; semantic overlap in `browser_profile_lease.py` and `browser_provisioner.py` was checked with the combined suites. One existing `PipeBrowser.__new__` test fixture needed initialization for the new transfer/quarantine state; production fallback was not loosened. The independent review then reproduced an applied source begin whose reply was lost: the manager had no ticket to release and stranded the source public CDP. The repair supplies a manager-generated private transaction identifier tied to exact owner lease and original CDP generation, idempotent begin replay, and ticket/transaction/owner/generation matching for every privileged operation. A recovered begin is explicitly released without importing any auth; double failure returns a side-specific cleanup-incomplete status unless exact adapter identity proves it available. The source is never stopped to resolve begin uncertainty.

The next review found that after an import, an applied source `/transfer/end` with lost reply and unprovable release returned `source-cleanup-incomplete` before destination disposal. The candidate repair resolves source identity first, then attempts exact recorded destination stop before returning. `stop_recorded` checks recorded unit invocation and verifies unit inactivity, process-root terminal state and old CDP unavailability; failed or unproved stops remain `cleanup-incomplete`. The source is never stopped or claimed released when its identity probe cannot prove release. The response reports sanitized source and destination dispositions without a CDP URL or auth data. Post-import source recheck failures also keep the recipient private until exact disposal, instead of aborting it back to public CDP. The unproved source path cannot commit/activate the recipient.

The follow-up transaction boundary holds the manager/canonical locks through an outer `finally`: any escaping post-import `BaseException` (including cancellation during source end or recheck) attempts exact recorded destination disposal before propagation. The original exception is not swallowed; a sanitized exception note distinguishes verified disposal from `destination=cleanup-incomplete`, conservatively marks source release unverified, and never exposes auth or CDP URLs. The destination's old public URL remains quarantined/fenced pending verified stop. The deterministic failed-stop clock now allows one real `stopped()` poll and asserts unit, process-root, and CDP verification reach their applicable gates; earlier green failed-stop cases did not exercise those checks.
