# Manual finding class input and sync behavior

`Class:` is optional; use it when known. Field values are open vocabulary (including the literal `unknown`) and use the existing lower-case, underscore/space-to-hyphen normalization. `Class:`, `**Class:**`, `**Class**:`, and the report metadata alias `Discovered During Class Pass:` are supported, including class fields prefixed by `-`, `*`, `+`, or an ordered marker such as `1.` or `1)` (one to nine digits). Repeated nonempty declarations in one finding must normalize to the same value. This extension is specific to class decisions; other field parsing is unchanged.

A Markdown `## Class` (any heading level) accepts one following nonblank value line; `## Class: idor` is also accepted. Heading values may be a single unformatted token such as `custom/v1`, the same single token enclosed in one pair of backticks (for example, `` `idor` ``), a bold value such as `**broken access control**`, or a value prefixed by an unordered marker (`-`, `*`, or `+`), such as `- broken access control`. Ordered heading values such as `1. idor` or `2) idor` are rejected as ambiguous; use a `Class: idor` field instead, optionally prefixed by an ordered marker as described above. An unmarked multiword heading value is ambiguous with prose and is rejected: write `Class: broken access control` or use bold or an unordered marker for the heading value. Other ambiguous heading values are rejected with the same instruction. A following field, heading, code block, or end of file leaves the heading empty. Empty class declarations do not override a nonempty one; if no explicit value exists, keyword inference applies (and manual hunter warns). Recognized fenced and four-space/tab-indented code is not parsed as class metadata or used for class inference, including list-nested and blockquoted fences (including nested blockquotes), subject to the limitation below. A valid opening fence without a valid closing fence suppresses code until EOF or until its list/blockquote container ends; shorter, different-character or otherwise invalid closing markers do not end it. An invalid opening marker is ordinary text, not a fence. Ordinary blockquoted prose remains available for inference; inferred keywords outside code still cannot distinguish negation from assertion.

This is a targeted recognizer, not a complete CommonMark parser. In particular, a list-item line with enough spaces after its marker to form indented code (for example `-     Class: ssrf`) may still be treated as a class declaration. Use fenced code for examples; this list-item-line indented-code case remains unresolved.

For sync reports using `## [TIER] title` finding headings, class and tier decisions are checked independently within each finding. Report-prelude class declarations are not defaults and do not conflict with or supply a finding's class; inference also uses only that finding's block. All findings in a report are checked for class and tier input conflicts before any finding from that report is written; a conflicting report is skipped. Multi-finding structured reports retain the structured reader's other fields rather than merging flexible-parser guesses; the existing single-finding whole-file merge remains for other metadata. A batch of separate report files is **not transactional**: other files may be imported even when one file is rejected. The command reports imported and skipped counts and exits 1 if any class/tier decision or FID collision requires attention, even if earlier files succeeded; exit 0 does not imply a new finding was created (duplicates may be skipped). Ledger reservations, FID collisions, and packet/index or other I/O failures encountered during sequential writes are not rolled back, including within a report. Inspect the summary and ledger before retrying.

For direct manual hunter CLI class errors, the diagnostic is printed without a traceback and exits 1. A linked duplicate also exits 1; inspect the message and ledger to distinguish it from a rejection.
