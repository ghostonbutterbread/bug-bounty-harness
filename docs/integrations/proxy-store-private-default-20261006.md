# Proxy Store private creation defaults

- **Feature branch:** `fix/proxy-store-private-default-20261006` (based on `origin/beta` at `59e72403600c9e9035081ca32e7ac5c64f3bbd83`).
- **Scope:** `skills/chromium-test/scripts/proxy_store.py` and `agents/test_proxy_store.py`; no captured packets accessed and no live target traffic.
- **Current defect:** In a synthetic store under umask `022`, SQLite created a database at `0644` and the dedicated directory at `0755`. The bounded, read-only selected-Hoster check found its *existing* database at `0600`, dedicated directory at `0755`, home at `0750`, and selected beta checkout clean at `bdce1f39cb277b43ccd7ee8e95fa2df35f1ae975`; this does not establish existing captured-data exposure. The fix prevents a recreated/default or explicitly chosen DB from inheriting permissive file bits.
- **Fix:** `connect` creates default directory `0700` and tightens an existing default directory, precreates or opens DB with atomic `0600` creation, and applies `fchmod(0600)` before SQLite opens it. Custom DB parent directories are not chmodded, avoiding unrelated shared-directory changes. An existing writable custom DB is also tightened to `0600`. Existing file content is not read or migrated by the permission operation.
- **Red/green:** The new test failed before change (default directory `0755` instead of `0700`) and passed afterward; it checks both fresh and existing `0644`/`0755` fixture repair. `agents/test_proxy_store.py agents/test_mitm_lane.py agents/test_hoster_mitm_lane.py`: 25 passed in 26.92s.
- **Risk/rollback:** Existing writable DB mode may tighten at next connect; prior group-reader workflows on custom DB files would need a separate explicit sharing design. Dedicated default directory tightening prevents traversal by other accounts while preserving same-owner access. Revert the feature commit if operationally incompatible; never broaden modes to recover captured-data access without owner authorization.
- **Reviewer focus:** Inspect creation-race avoidance, default path comparison, symlink/custom-parent behavior, SQLite sidecars (`-wal`, `-shm`), and compatibility with existing DBs/CLI queries. Beta publication and Hoster selected-checkout activation are separate steps.
