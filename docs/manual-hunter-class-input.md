# Manual finding class input and sync behavior

`Class:` is optional; use it when known. Field values are open vocabulary (including the literal `unknown`) and use the existing lower-case, underscore/space-to-hyphen normalization. `Class:`, `**Class:**`, `**Class**:`, list-prefixed fields, and the report metadata alias `Discovered During Class Pass:` are supported. Repeated nonempty declarations in one finding must normalize to the same value.

A Markdown `## Class` (any heading level) accepts one following nonblank value line; `## Class: idor` is also accepted. Heading values may be a single unformatted token such as `custom/v1`, or a bold or list-marked value such as `**broken access control**` or `- broken access control`. An unmarked multiword heading value is ambiguous with prose and is rejected: write `Class: broken access control` or mark the heading value explicitly. Other ambiguous heading values are rejected with the same instruction. A following field, heading, fence, or end of file leaves the heading empty. Empty class declarations do not override a nonempty one; if no explicit value exists, keyword inference applies (and manual hunter warns). Fenced code is not parsed as metadata or used for class inference; inferred keywords outside fences still cannot distinguish negation from assertion.

For sync reports using `## [TIER] title` finding headings, class and tier decisions are checked independently within each finding. All findings in a report are checked for class and tier input conflicts before any finding from that report is written; a conflicting report is skipped. A batch of separate report files is **not transactional**: other files may be imported even when one file is rejected. The command reports imported and skipped counts and exits 1 if any class/tier decision or FID collision requires attention, even if earlier files succeeded; exit 0 does not imply a new finding was created (duplicates may be skipped). Ledger reservations, I/O failures, and FID collisions encountered during writing are not rolled back, including within a report. Inspect the summary and ledger before retrying.

For direct manual hunter CLI class errors, the diagnostic is printed without a traceback and exits 1. A linked duplicate also exits 1; inspect the message and ledger to distinguish it from a rejection.
