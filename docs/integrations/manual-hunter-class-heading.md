## Contract and compatibility

The class parser is shared by direct and sync import and honors explicit `unknown`, open vocabulary, aliases and normalized agreement. It excludes fenced and indented code, including list-nested fences, and stops class headings at fields, headings, code and EOF. Plain unmarked heading values are single tokens; a single token in one pair of backticks is also accepted. Multiword values must be marked bold/list or given as a `Class:` field. Ambiguous heading prose is rejected with an actionable diagnostic, not guessed. Code contents no longer contribute to keyword class inference; absent/empty explicit class still infers, with the existing warning in manual hunter. See `docs/manual-hunter-class-input.md` for syntax and exit semantics. Direct CLI catches class decision errors without a traceback.

Structured sync validates every block's class and tier decision before returning candidates for any write; independently selected tiers no longer bypass block conflict checks. Explicit values and inference are scoped to each block, including the single-finding flexible merge; prelude classes are not defaults and do not conflict with findings. Multi-finding structured metadata comes from the structured reader, not a flexible per-block merge; beta's existing whole-file merge for other fields of a single finding is retained, including its pre-existing guesses. Different report files are not a batch transaction. The importer still performs mutating ledger reservation/FID collision checks sequentially after candidate validation, and does not roll back FID collisions or packet/index/I/O failures. Thus it does **not** guarantee all possible validations or atomic writes across a report; do not represent it as doing so.
